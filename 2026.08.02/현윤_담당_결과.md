# 정리·문서화

## 1. 현재 최고 리더보드 점수를 기록한 코드 버전 확정

- **최고 버전: v32 → 리더보드 총점 0.63625** (1−NMAE 0.87118 / **FICR 0.40133**)
- `model_A.py`로 **재현 검증 완료**:
  - 2-fold: fold A 0.6125, fold B 0.6382 (원본 v32와 ±0.0004 이내)
  - 최종 예측 `submit_A.csv` vs 원본 v32 **상관 1.00000** (동일)
- 세션 개선 흐름: 0.6284 → 0.6290(다양성) → 0.6297(튜닝) → 0.6322(보정) → 0.6345(격자) → **0.63625(격자풍향)**

## 2. 최종 사용 피처 목록 정리

- **총 192개** (기본 피처 + 격자별 피처 + lag/lead + base_means → gain 중요도 하위 30% 가지치기 후)
- 그룹별:
  - **시간**: month, hour, hour_sin/cos, doy_sin/cos
  - **LDAPS 바람**: l10/l50 풍속(mean/std/min/max), 돌풍(gustmax), 풍속³(ws3), 발전량프록시(power_proxy), 근접격자, 풍향(dir_sin/cos)
  - **LDAPS 대기**: 공기밀도(rho), 온도, 습도, 기압, 경계층높이(blh), 하층운(lcc), 강수·강설
  - **GFS 바람**: g10/g80/**g100(허브)**/**g850(상공)** 풍속·ws³, 집계, 풍향
  - **GFS 기타**: 돌풍, 환기율(VRATE), 전운량(tcc), 강수율(prate)
  - **시간변화(ramp)**: diff, roll3, lag/lead
  - **격자별 피처**: LDAPS 16격자·GFS 9격자의 풍속(ws10/ws50/ws50³, ws100/ws80/ws850/ws100³) + 풍향(sin/cos)
  - **예보/그룹**: lead_hours, group_id

## 3. LDAPS와 GFS 격자별 피처 생성 코드 정리

`model_A.py`의 `pergrid()`, `pergrid_dir()` 함수. 격자를 **평균 내지 않고 각각** 컬럼으로.
- **풍속**: 격자별 `ws=√(u²+v²)` → pivot (LDAPS 16 + GFS 9 격자)
  - LDAPS: 10m(ws10), 50m(ws50), 50m³(ws50³)
  - GFS: 100m(ws100), 80m(ws80), 850hPa(ws850), 100m³(ws100³)
- **풍향**: 격자별 `dsin=v/ws, dcos=u/ws` (LDAPS 10m, GFS 100m)
- 효과: 후반부 최대 개선원 (v28 격자풍속 +0.0022, v32 격자풍향 +0.0014)

## 7. 발전량 가중치, 10% 컷, Calibration 적용 여부 정리

| 기법 | 적용 | 방식 |
|------|:---:|------|
| 발전량 가중치 | ✅ ON | sample_weight = 0.5 + y/용량 (고발전 시간 강조) |
| 10% 컷 | ✅ ON | 발전량 < 용량10% 시간 학습 제외 (채점 제외 구간) |
| Calibration | ✅ ON | **group1만**, 발전량 구간별 편향 보정(debias), 2024로 fit |
| 스무딩 | ✅ ON | 예보블록 내 3시간 이동중앙값 |
| 클리핑 | ✅ ON | 0 ~ 설비용량 |

## 8. Group3 SCADA 라벨 정제 방식 정리

- g3 = **unison 단지** (라벨 ≈ unison SCADA 합계, 상관 0.997)
- **정제(디노이징)**: 라벨과 unison SCADA 시간합계가 **1000kWh 초과** 어긋난 시간 = 라벨 오류로 보고 **학습에서 제외**
- **통합학습(pooled)**: g3는 데이터가 상대적으로 적어 g1·g2와 합쳐 한 모델로 학습(용량 정규화 + group_id)
- (참고: g1·g2는 vestas 단지지만 vestas가 35% 부분표본이라 디노이징 부정확 → 미적용)

# Ablation (할 일 참고) — 각 요소 기여도

> 각 요소를 빼거나 바꿔서 2-fold 점수 변화를 측정. **fold B Δ가 음수일수록 그 요소가 크게 기여**(빼면 점수 하락). (3시드 스크리닝)
> **기준(전체 앙상블): fold A 0.6129 / fold B 0.6384**

## LightGBM 단독
- fold A 0.6114 / fold B 0.6379 (기준 대비 **−0.0005**) → LightGBM 하나로도 강함. Cat+XGB 다양성 기여는 소폭.

## LightGBM과 XGBoost 앙상블
- fold A 0.6126 / fold B **0.6385** → 전체(0.6384)와 거의 동일. **CatBoost 기여 ~0**(있으나 마나).

## LightGBM, XGBoost, CatBoost 전체 앙상블 (= 기준)
- fold A 0.6129 / fold B 0.6384 → 최종 채택 구성.

## 격자별 피처 제거
- fold A 0.6115 / fold B 0.6352 (**−0.0032**) → **격자 피처가 3번째로 큰 기여**. 빼면 크게 하락.

## Group3 라벨 정제 제거
- fold A 0.6129 / fold B 0.6366 (**−0.0018**) → g3 정제가 유의미 기여(fold A는 g3 없어 불변).

## Calibration 제거
- g1 fold B: **무보정 0.6409 → 보정 0.6681 (Δ+0.0271)** (2023학습→2024 OOS)
- g1 한 그룹에서 큰 효과. 전체 3그룹 기준 약 +0.009 기여.

## 앙상블 비율 변경 (→ 균등 1/3)
- fold A 0.6127 / fold B 0.6373 (**−0.0011**) → 튜닝 비율(0.5/0.1/0.4)이 균등보다 좋음(CatBoost 과중 시 하락).

## 시드 평균 개수 변경 (3 → 1)
- fold A 0.6138 / fold B 0.6378 (**−0.0006**) → 시드 평균이 소폭 기여(분산 축소).

### 🎯 핵심 인사이트
**가장 큰 기여는 화려한 모델이 아니라 "채점 방식에 학습을 정렬한 것"이었다:**
1. **10% 컷**(−0.0109) — 대회가 저출력 시간을 채점 안 하니 학습도 제외
2. **발전량 가중치**(−0.0059) — 점수가 발전량 가중이니 학습도 발전량 가중
3. **격자 피처**(−0.0032) + **g3 라벨정제**(−0.0018) — 데이터·공간 정보
4. Calibration은 g1에서 강함(+0.0271). CatBoost 기여는 미미(~0).

## 데이터 전처리 (참고 — 초기 작업)
- SCADA(vestas·unison) 원시 센서 데이터 정제: **부호쌍 오류(음양 반복)**, 비정상 음수→0, 극단 이상치 제거, 물리 불가능값 결측화
- 기상데이터(LDAPS/GFS)는 결측·이상치 거의 없음(모델 출력이라 깨끗). LDAPS 습도 100% 초과(과포화 아티팩트) 약 4%만 존재.
- 검증: 시간순 2-fold(2023 학습→2024 / 2024 학습→2025). **양쪽 fold 다 개선될 때만 제출**(과적합 방지 게이트).
