# 데이터 쉽게 이해하기 — BARAM 2026 풍력발전량 예측

팀 공유용 요약본. 자세한 근거/수치는 `docs/eda_report.md` 참고.

## 1. 우리가 맞춰야 하는 것

**목표**: 2025년 한 해(시간별, 8,760시간) 동안 풍력발전소 3곳의 발전량(kWh)을 예측.

세 발전소(정확히는 KPX 정산그룹 3개)는 이런 구성:

| 그룹 | 실체 | 터빈 수/모델 | 설비용량 |
|---|---|---|---|
| kpx_group_1 | VESTAS 단지 앞쪽 6기 | V126 6기 | 21.6 MW |
| kpx_group_2 | VESTAS 단지 뒤쪽 6기 | V126 6기 | 21.6 MW |
| kpx_group_3 | UNISON 단지 | U136 5기 | 21.0 MW |

즉 물리적으로는 **2개 풍력단지**(VESTAS 단지, UNISON 단지), 정산은 **3개 그룹**으로 나뉨(VESTAS 단지가 그룹1/2로 쪼개짐).

## 2. 왜 어려운가

일반적인 "지난 발전량 보고 다음 발전량 예측" 문제가 **아님**. 평가 기간(2025년)엔 과거 실적/SCADA를 전혀 못 씀 — 오직 **하루 전 기상예보**만 갖고 맞춰야 함. 그래서 이건 순수하게 "날씨 → 발전량" 회귀 문제.

## 3. 파일 구성

```
train/
  ldaps_train.csv        기상예보 A (LDAPS, 1.5km 격자 16개)   — 학습기간
  gfs_train.csv          기상예보 B (GFS, 0.25도 격자 9개)     — 학습기간
  train_labels.csv       실제 발전량(정답)                     — 학습기간
  scada_vestas_train.csv VESTAS 터빈 12기 실측(10분단위)        — 학습기간만 존재
  scada_unison_train.csv UNISON 터빈 5기 실측(10분단위)         — 학습기간만 존재
test/
  ldaps_test.csv, gfs_test.csv   기상예보 (2025년, 예측해야 하는 기간)
info.xlsx                 터빈 위치/용량 메타정보
sample_submission.csv     제출 양식
```

**핵심**: `scada_*`는 train에만 있고 test엔 없음 — 모델 입력으로 직접은 못 씀(미래 시점엔 존재하지 않는 데이터라서). 대신 "이 단지는 풍속 몇 m/s일 때 대략 몇 kW 내더라" 하는 **파워커브를 학습하는 용도**로 쓸 수 있음(학습기간에서 커브를 뽑아서, 예보 풍속에 그 커브를 적용하는 식).

## 4. 시간 단위가 다르다

| 파일 | 시간 단위 |
|---|---|
| train_labels, ldaps/gfs | **1시간** |
| scada | **10분** |

SCADA는 시간당 6개 행이 있는데, 이걸 시간 단위로 뭉칠 때 **평균이 아니라 합산**해야 함(자세한 이유는 6번 항목).

## 5. 날씨 데이터가 "그리드"로 되어 있다

풍력단지 하나에 딱 하나의 날씨값이 있는 게 아니라, 단지 주변 여러 지점(LDAPS는 16개, GFS는 9개)의 예보가 각각 따로 주어짐. 그래서 "이 그리드들을 어떻게 우리 단지 하나의 대표값으로 합칠까"가 피처엔지니어링의 첫 관문 — 단순평균 / 가장 가까운 격자 하나 쓰기 / 거리가중평균(IDW) 세 방법을 다 시도해볼 것(EDA 결과 그룹마다 유리한 방법이 다름, `eda_report.md` §Open Questions #7 참고).

바람은 "풍속" 대신 **u(동서성분)/v(남북성분)** 두 숫자로 옴 — `풍속 = sqrt(u²+v²)`로 직접 계산해야 함.

## 6. 실수하기 쉬운 지점 (EDA로 검증된 함정들)

- **SCADA 컬럼명이 오해 소지 있음**: `*_power_kw10m`이라고 되어 있어서 "이건 순간 전력(kW)이다"라고 생각하기 쉬운데, 실제로는 **10분간 발전한 에너지(kWh)**임. 시간당 값 만들 때 6개 값을 평균 내면 실제 발전량의 1/6로 나옴 — **합산**해야 정답 라벨과 거의 정확히 일치함(상관 0.9998로 검증).
- **타임스탬프 조인은 그냥 같은 시각끼리 맞추면 됨**: `forecast_kst_dtm`(날씨 예보 시각) = `kst_dtm`(발전량 라벨 시각). 시차 안 줘도 됨 — EDA에서 여러 시차를 다 테스트해서 확인함.
- **SCADA에 이상치 있음**: Vestas 데이터에 0.05% 정도 터무니없이 큰 값(수백만 단위)이 섞여 있음 — 센서/로깅 버그로 보임. 파워커브 만들기 전에 걸러내야 함.
- **제조사마다 풍향 표기가 다름**: Vestas는 0~359도, Unison은 -180~180도. 방향 자체는 같은 컴퍼스 방위라서 `%360`만 해주면 맞춰짐(별도 변환 불필요, EDA로 확인됨).
- **날씨 데이터의 50m 최대/최소 풍속 필드는 "속도"로 쓰면 안 됨**: LDAPS의 `MUmax/MUmin/MVmax/MVmin`은 한 시간 내 U성분 최대값과 V성분 최대값을 각각 따로 기록한 것이라, 이 둘을 합쳐서 "최대 돌풍 속도"를 계산하면 틀림(동시에 발생한 값이 아님). 네 개를 각각 독립적인 숫자로만 쓸 것.

## 7. 예측이 실제로 채점되는 시간은 절반 정도뿐

발전량이 설비용량의 **10% 미만인 시간은 평가에서 아예 제외됨**. 그룹별로 전체 시간의 약 39~46%가 여기 해당함 — 즉 "바람이 거의 안 부는 시간"을 완벽히 0으로 맞춰도 점수엔 전혀 반영 안 됨. 반대로 CV 점수 볼 때도 이 마스크(10% 이상만) 적용해서 봐야 실제 리더보드 점수랑 비슷하게 나옴.

## 8. 그룹별로 데이터 양이 다르다

- kpx_group_1, kpx_group_2: 2022년부터 라벨 있음
- kpx_group_3: **2023년부터**만 라벨 있음(2022년 전체 없음) — 학습 데이터가 1년 적음. 그룹3은 상대적으로 더 단순한 모델/더 강한 정규화를 고려할 것.

## 9. 한 장 요약

```
날씨예보(LDAPS+GFS, 그리드 여러개, 하루 전 확정)
        ↓  그리드 → 단지 대표값으로 합치기 (mean/nearest/IDW)
        ↓  u,v → 풍속/풍향 계산
        ↓  시간 특징(월/시간대) 추가
   피처 테이블 (시간당 1행)
        ↓
   모델 (그룹별 회귀) → 발전량(kWh) 예측
        ↑
   (참고용) SCADA 실측 → 단지별 파워커브 → 피처로 활용 가능 (train만)
```
