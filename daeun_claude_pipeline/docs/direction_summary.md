## 1. 문제 정의

3개 KPX 정산그룹(`kpx_group_1/2/3`)의 시간당 발전량(kWh)을, 오직 **하루 전 기상예보(LDAPS+GFS)** 만으로 2025년 전체(8,760시간) 예측. 실적/SCADA 데이터는 테스트 기간엔 전혀 없음 — 순수 "날씨→발전량" 회귀 문제, 시계열 자기회귀 문제가 아님.

| 그룹 | 제조사/터빈 | 용량 | 라벨 시작 |
|---|---|---:|---|
| kpx_group_1 | VESTAS V126 ×6 | 21.6 MW | 2022-01 |
| kpx_group_2 | VESTAS V126 ×6 | 21.6 MW | 2022-01 |
| kpx_group_3 | UNISON U136 ×5 | 21.0 MW | 2023-01 (2022년 결측) |

**평가지표** (2026-07-26 평가페이지에서 직접 확인, 이미지로만 렌더링돼서 base64 디코딩으로 확보):

```
Total = 0.5 × (1-NMAE) + 0.5 × FICR
NMAE(그룹) = mean(|예측-실적| / 그룹설비용량)          — 적격시간만(실적≥설비용량10%)
FICR(그룹) = 획득정산금 / 이론상최대정산금
  시간별 정산단가: NMAE≤6% → 4원/kWh, 6~8% → 3원/kWh, 8%초과 → 0원
```

이 지표가 사실상 모든 설계 결정의 근거. 특히 **적격시간 마스킹**(전체 시간의 39~46%가 아예 채점 제외, `eda_report.md` §3)과 **FICR의 계단함수 특성**(평균 오차가 작아도 시간별로 8% 밴드를 자주 벗어나면 점수가 확 깎임) 두 가지가 이후 모든 이슈의 뿌리.

## 2. 파이프라인 구조 — 무엇을, 왜

```
data/open/{train,test}  ─┐
info.xlsx (그룹→좌표)    ─┼─▶ src/features.py ─▶ 그룹별 design matrix ─▶ src/model.py (LightGBM) ─▶ src/submission.py ─▶ submissions/*.csv
train_labels.csv         ─┘         ▲
                                     └─ src/cv.py (시간순 CV) + src/metrics.py (NMAE/FICR)
```

### 왜 그룹별 독립 모델 3개인가 (공유 모델 아니고)

`eda_report.md` §2: 세 그룹이 제조사(VESTAS vs UNISON)도, 좌표도, 라벨 이력 길이(그룹3은 1년 적음)도 다름. §3에서 그룹3이 저CF 꼬리가 확연히 두꺼운 것도 확인(사이트 특성이지 데이터 적음의 부산물이 아님). "3개의 관련되었지만 별개인 문제"로 취급 — 그룹 임베딩을 넣은 단일 모델보다 그룹별 독립 모델이 더 단순하고 이 정도 데이터 규모(그룹당 2~3만 행)에선 굳이 공유할 이유가 약함.

- **장점**: 그룹별로 하이퍼파라미터/피처 선택(그리드 축소 방식 등)을 독립적으로 튜닝 가능, 한 그룹의 노이즈가 다른 그룹 학습에 새지 않음.
- **단점**: 그룹1/2처럼 같은 제조사·비슷한 좌표인 그룹 간에 공유될 수 있는 신호(예: 공통 날씨 패턴)를 모델이 각자 처음부터 다시 배워야 함 — 데이터가 적은 그룹3 입장에선 그룹1/2의 더 풍부한 이력을 전혀 못 씀. 그룹3의 NMAE가 셋 중 항상 제일 낮은 것도 이와 무관하지 않을 가능성.

### 타겟 정규화: kWh가 아니라 capacity fraction(=kWh/설비용량)으로 학습

PLAN.md §1.3, NMAE 정의 자체가 분모를 고정 설비용량으로 쓰기 때문에, 그룹 간 손실 스케일을 맞추려면 이렇게 정규화하는 게 자연스러움. 부산물로 그룹별 손실 크기가 비교 가능해짐.

### CV: 시간순 확장창(expanding-window) 4-fold, 랜덤 셔플 금지 (`src/cv.py`)

테스트 기간엔 미래 실적을 절대 못 쓰는 문제이므로, 무작위 K-fold를 쓰면 "미래 데이터로 과거를 예측"하는 리크가 생김. 확장창은 각 fold가 그 이전 시점 데이터만으로 다음 구간을 예측 — 실제 대회 조건과 동일한 제약.

- **장점**: 리크 없음, 구현 단순, fold별 학습량 증가 추이도 볼 수 있음.
- **단점(이번에 실측으로 드러남, 아래 §5 참고)**: 4개 fold 전부 2022~2024(학습 기간) *안에서* 뽑히기 때문에, 진짜 테스트 기간(2025, 완전히 밖에 있는 미래 1년)과의 분포 차이는 전혀 반영 못 함. 평균을 내면 fold별 불안정성도 가려짐 — 실제로 이 평균 CV가 이후 두 번이나 실측과 반대 방향을 가리켰음.

## 3. 모델: LightGBM — 왜 이걸 골랐고, 장단점

**선택 이유** (PLAN.md §1.5 우선순위):
- 정형(tabular) 데이터 + 몇십 개 피처, 행 수도 그룹당 2~3만 — 이 규모/형태에서 GBM 계열이 준수한 시작점이자 학습/추론이 빠름(피처 반복이 쉬움).
「PLAN.md 원안」은 LightGBM/CatBoost를 먼저, LSTM/TFT 등 시퀀스 모델은 "1~4단계가 탄탄해지고 시간 남으면"으로 뒤로 미룸 — 아직 그 뒤 단계는 안 감.

**장점**: 결측 자동 처리, 비선형/상호작용을 알아서 학습(파워커브의 시그모이드형 비선형성도 원시 풍속만 줘도 스스로 찾음 — `eda_report.md` §4 "Spearman > Pearson" 근거), 학습이 몇 초~수십 초라 실험 반복이 빠름(이번 세션에서 objective/그리드축소/보정 여러 조합을 몇 분 안에 A/B 가능했던 이유).

**단점**: 
- 트리 기반이라 학습 데이터 범위 밖 외삽을 못 함(다만 §4 실험에서 테스트기간 예측값이 OOF 범위 안에 99%+ 들어왔던 걸 보면 지금은 크게 문제는 아닌 듯).
- objective가 대회 지표(NMAE 평균 + FICR 계단함수)와 정확히 일치하지 않음 — L2든 L1이든 결국 매끄러운 손실함수를 최소화할 뿐, "8% 밴드 안에 들어오는가"라는 진짜 보상 구조를 직접 겨냥하지 못함(§6에서 다시 다룸).
- 단일 모델 — 앙상블/블렌딩 없음(PLAN.md 우선순위 4번, 아직 미착수).

**objective 변경 (`regression` L2 → `regression_l1` L1)**: 대회 지표가 정확히 MAE 기반인데 L2(제곱오차)를 최소화하던 게 이론적 미스매치였음. L1로 바꾼 뒤 실측 확인됨(§5) — 지금까지 실측으로 확정된 유일한 순수 개선.

## 5. 검증(CV/holdout)과 실측의 괴리 — 이번 세션 최대 교훈

### 제출 이력 (실측, 리더보드)

| 회차 | 구성 | 1-NMAE | FICR | Total | CV/holdout 예측 | 실측과 맞았나 |
|---|---|---:|---:|---:|---|---|
| 1차 | L2, mean 그리드, 보정없음 | 0.8660 | 0.3402 | 0.6031 | (FICR 미구현 상태로 제출) | 기준점 |
| 2차 | L1 + isotonic 보정 | 0.8621 | 0.3287 | 0.5954 | 다중폴드 CV: 0.5851(↑ 예측) | **틀림** — 실제로 내려감 |
| 3차 | L1만(보정 롤백) | 0.8650 | 0.3467 | **0.6059(최고)** | 단일 holdout: 0.6241(↑ 예측, 방향은 맞음) | **맞음** — 확정 개선 |
| 4차 | L1 + 그룹별 그리드축소 | 0.8654 | 0.3435 | 0.6044 | 단일 holdout: 0.6291(↑ 예측) | **틀림** — 실제로 소폭 내려감(-0.0014, 노이즈권) |

### 왜 검증이 두 번이나 틀렸나

1. **다중 폴드 평균 CV**는 fold별 불안정성을 평균으로 가림. isotonic처럼 그룹별로 부호가 정반대로 튀는 방법(그룹1은 크게 개선, 그룹2/3은 악화)은 평균만 보면 "좋아 보임" — 실제 배포(모델 하나, 데이터 하나)에서는 그 불안정성이 그대로 드러남.
2. **단일 last-block holdout**(마지막 15%를 미래처럼 떼어놓는, 더 엄격한 방법)으로 바꾼 뒤에도 여전히 한 번 틀림(4차) — 근본 원인은 이 holdout도 결국 **학습 기간(2022~2024) 안**의 데이터일 뿐, 진짜 테스트 기간(2025, 완전히 밖의 미래 1년)과는 다른 분포일 수 있다는 것. **학습기간 내부에서 아무리 엄격하게 잘라도 out-of-time 진짜 미래를 완벽히 대신할 수 없음.**
3. **FICR의 계단함수 특성**이 이 괴리를 증폭시킴 — 평균 오차가 아주 조금만 달라져도, 그게 6%/8% 밴드 경계를 넘나드는 시간이 많아지면 점수가 꽤 크게 흔들림. 이래서 NMAE는 거의 안 변해도 FICR만 확 움직이는 패턴이 반복됨(2차, 4차 둘 다 이 패턴).

### 지금부터의 원칙 (`submission_log.md`에도 기록)

- **±0.005 수준의 holdout 개선은 노이즈로 취급.** 그 정도 차이는 두 번 다 실측에서 뒤집혔음.
- 방향을 바꿀 만한 근거는 **크기가 뚜렷하거나(예: L1 objective, 이론적 근거+실측 둘 다 확인됨), 구조적으로 새 정보를 추가하는 변화(새 피처)** 여야 신뢰.
- 자잘한 하이퍼파라미터/전처리 선택(그리드 축소 방식, 보정 방식)은 **실측으로 뒤집힐 각오를 하고, 확신 없으면 그냥 손대지 않는 게 기대값이 더 나을 수 있음.**

## 6. 다음 방향성 (우선순위)

1. ~~**SCADA 기반 물리 파워커브 피처**~~ — **시도함, 채택 안 함**(`submission_log.md` "실험(미채택)" 참고). `src/power_curve.py`로 구현(글리치 필터링, 풍속 보정, 구간화+isotonic 커브)해서 단일 holdout으로 검증했는데, 단변량 상관은 raw 풍속보다 좋았지만(0.75 vs 0.73) 실제 GBM 총점엔 도움 안 됨(오히려 소폭 하락) — LightGBM이 트리 분기로 이 비선형을 이미 원시 풍속만으로 잡아내는 걸로 보임. 재시도한다면 피처 주입이 아니라 **블렌딩 성분**(GBM 예측과 파워커브 예측의 가중평균)으로 — 미시도.
2. **FICR을 직접 겨냥한 손실함수/보정** — 지금은 L1(매끄러운 대리 손실)이 전부. 8%/6% 밴드 경계를 직접 겨냥하는 커스텀 objective(예: 밴드 경계 근처에서 그래디언트를 키우는 형태)나, 최소한 **더 규제된(overfitting 덜 되는) 보정**(예: 세밀한 isotonic 대신 소수 구간짜리 binned 보정, 또는 단순 선형 보정)을 **반드시 단일 last-block holdout으로 먼저 검증**한 뒤 시도.
3. **앙상블/블렌딩** (PLAN.md 우선순위 4번) — LightGBM 단일 모델 뿐. XGBoost/CatBoost 등 다른 GBM 변종 + 위 SCADA 물리 모델을 블렌딩하면, 특히 모델 종류가 다른 데서 오는 분산 감소가 FICR처럼 꼬리에 민감한 지표에 도움이 될 가능성.
