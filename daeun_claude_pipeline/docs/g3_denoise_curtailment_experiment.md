# g3 denoise/커튼먼트/longzero 마스크 실험 (담당: 윤다은)

**스크립트:** `run_g3_denoise_experiments.py`(model_A.py는 수정하지 않음, read-only import로
`g3mask`/`_sw`만 monkeypatch). 데이터·모델·하이퍼파라미터는 전부 `model_A.py` 그대로.
**검증:** fold B(2023 학습 → 2024 검증), model_A.py 자체 `gscore()` 사용.
**출처:** [[scada_label_crosscheck_g3.md]] 진단 결과(커튼먼트 후보 51시간 오차율이 평균의
4.11배, denoise 마스크는 실제 오차와 무관)를 실제 학습 실험으로 검증.

---

## 1. 변형 정의

| 변형 | 방식 |
|---|---|
| V0_baseline | 현재 코드(`g3mask`, SCADA-라벨 잔차>1000 제외) 그대로 |
| V1_curtail_excl | baseline + 커튼먼트 후보(풍속>8m/s & SCADA출력<정격10%) 추가 제외 |
| V2_longzero_excl | baseline + `kpx_group_3_longzero=1` 추가 제외 |
| V3_both_excl | baseline + 커튼먼트 + longzero 둘 다 제외 |
| V4_curtail_only | 기존 denoise(잔차>1000) **끄고** 커튼먼트+longzero 제외만 사용 |
| V5_downweight | 제외 대신 커튼먼트+longzero 시점 `sample_weight`를 0.3배로 다운웨이트(데이터는 유지) |

## 2. 결과 (fold B = 2024, macro 순)

| variant | g1 | g2 | g3 | **macro** | g3 학습표본수 |
|---|---:|---:|---:|---:|---:|
| **V5_downweight** | 0.6429 | 0.6732 | 0.6003 | **0.6388** | 17,004 |
| V1_curtail_excl | 0.6403 | 0.6715 | 0.6013 | 0.6377 | 16,966 |
| V3_both_excl | 0.6403 | 0.6715 | 0.6013 | 0.6377 | 16,856 |
| V0_baseline | 0.6403 | 0.6715 | 0.6011 | 0.6376 | 17,004 |
| V2_longzero_excl | 0.6403 | 0.6715 | 0.6011 | 0.6376 | 16,894 |
| V4_curtail_only | 0.6403 | 0.6715 | 0.5963 | 0.6361 | 17,372 |

baseline(V0) macro 0.6376은 팀 기존 실측(0.6376, FICR 후처리 리포트 M0)과 일치 — 하네스 검증됨.

## 3. 해석

- **longzero 단독 제외(V2)는 g3 점수에 전혀 영향 없음**(0.60105 → 0.60105, 소수점까지 동일). 제외되는
  표본이 110건뿐이라 이미 큰 pooled 학습셋에 묻힘 — 이 축은 단독으로는 레버리지 없음.
- **커튼먼트 제외(V1)는 g3를 소폭 개선**(0.6011→0.6013, +0.0002) — 방향은 맞지만 크기는 작음.
- **기존 denoise를 끄면(V4) 확실히 나빠짐**(0.6011→0.5963, −0.0047) — 1000kWh 잔차 마스크는
  실제 2024 오차와는 무관해 보였지만(진단 리포트 참고) 학습 데이터 품질 자체에는 여전히 기여함 →
  **없애면 안 됨**, 유지 전제로 위에 얹는 방식만 검토해야 함.
- **제외보다 다운웨이트(V5)가 확실히 낫다 — macro 기준 유일하게 유의미한 개선(+0.0012)**.
  g3 자체는 baseline과 거의 같은데(0.6011→0.6003, 오차범위 수준 소폭 하락), **g1(+0.0026)·g2
  (+0.0017)가 같이 좋아짐**. 이유: `_sw`(sample_weight) 패치를 group3 전용이 아니라 전체 학습
  인덱스 기준으로 적용해서, 커튼먼트/longzero 시점이 g1·g2 학습에도 (farm이 다르지만 같은 시간대라)
  같이 다운웨이트됨 — 계통 차원 커튼먼트가 여러 그룹에 동시에 걸릴 수 있다는 정황과 일치.
  **단, 이건 의도한 효과가 아니라 패치 범위가 전역이라 생긴 부수 효과라 확인이 더 필요함**(g3만
  다운웨이트하는 버전과 비교 안 해봄 — 후속 실험 후보).

## 4. group3 전용 블렌드 비율 재탐색 (재학습 없음, 저장된 컴포넌트 재활용)

V1의 lgb/cat/xgb 개별 예측(재학습 없이 그대로 재사용)에 블렌드 비율만 그리드서치:

| lgb | cat | xgb | g3 score |
|---:|---:|---:|---:|
| 0.40 | 0.20 | 0.40 | **0.6021** |
| 0.30 | 0.20 | 0.50 | 0.6021 |
| 0.60 | 0.10 | 0.30 | 0.6019 |
| **0.50(기존)** | **0.10(기존)** | **0.40(기존)** | 0.6013 |

기존 전역 비율(lgb .5/cat .1/xgb .4) 대신 cat 비중을 0.1→0.2로 올리면 g3만 +0.0008 추가 개선.
CatBoost가 group3(잔차 큰 pooled 학습)에서 상대적으로 더 안정적인 것으로 보임.

## 5. 권고 및 다음 실험

1. **V5(다운웨이트)를 기본으로 채택 검토** — 지금까지 나온 것 중 macro 기준 유일한 순개선(+0.0012)
2. group3 블렌드는 cat 비중 상향(0.1→0.2)이 소폭이지만 공짜 개선(재학습 불필요) — 바로 반영 가능
3. **후속 실험**: V5(다운웨이트) 컴포넌트에 대해서도 §4와 같은 group3 전용 블렌드 재탐색 수행
   (다운웨이트+블렌드 재조정을 같이 적용하면 macro가 0.6388보다 더 오를 가능성) — 아직 안 돌려봄
4. V5의 g1/g2 개선이 진짜 "그룹 무관 커튼먼트 신호"인지, 단순히 전역 다운웨이트 패치의 우연한
   부수효과인지 구분하기 위해 **group3 전용으로만 다운웨이트하는 버전**과 비교 필요
5. 커튼먼트 제외(V1) 자체는 효과가 작아서(제외 방식으론) 단독 채택 우선순위는 낮음 — 다운웨이트
   방식(V5)이 이미 이걸 포함하면서 더 나음
