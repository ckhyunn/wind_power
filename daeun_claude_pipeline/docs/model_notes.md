# 모델 노트 — RandomForest & LightGBM

팀 발표용. "이 모델이 어떻게 동작하는지 / 왜 골랐는지 / 주요 파라미터"를 설명할 수 있게 정리.

---

## RandomForest (RF)

### 동작 원리

1. 학습 데이터에서 **부트스트랩 샘플**(중복 허용 랜덤 추출)을 여러 번 뽑는다.
2. 각 샘플마다 **결정트리**를 하나씩 학습시킨다. 이때 트리가 각 분기(split)를 정할 때 전체 피처가 아니라 **무작위로 고른 일부 피처**만 후보로 본다(`max_features`).
3. 트리 하나하나는 "풍속이 8m/s보다 큰가? → 그럼 온도가 5도보다 낮은가? → ..." 이런 식으로 데이터를 계속 쪼개서 각 leaf(말단 노드)의 평균값을 예측치로 삼는다.
4. 회귀에서는 **모든 트리의 예측값을 평균**낸 게 최종 예측.

핵심 아이디어는 **"서로 조금씩 다르게 틀리는 트리 여러 개를 평균 내면 개별 트리보다 안정적"** (bagging + 피처 랜덤성 = 분산 감소).

### 왜 이 문제에 적합한가

- 파워커브(풍속→발전량)가 **비선형이고 구간별로 기울기가 다름**(저풍속 완만 → 중간 급상승 → 고풍속 포화) — 트리 기반 모델은 이런 비선형/비단조 아닌 구간 관계를 선형모델보다 훨씬 잘 잡음.
- 피처 스케일을 안 맞춰도 됨(정규화 불필요) — u/v, 온도, 기압처럼 단위가 완전히 다른 피처를 섞어 써도 문제없음.
- 결측치나 이상치에 상대적으로 덜 민감(트리 분기는 순위만 보지 절대값 스케일에 안 흔들림).
- 하이퍼파라미터가 적고 튜닝 없이도 웬만큼 잘 나와서 **베이스라인으로 빠르게 세우기 좋음**.

### 주요 파라미터

| 파라미터 | 의미 | 실무 감 |
|---|---|---|
| `n_estimators` | 트리 개수 | 많을수록 안정적이지만 느려짐 (100~300 정도가 흔한 시작점) |
| `max_depth` | 트리 최대 깊이 | 너무 깊으면 과적합, 너무 얕으면 파워커브의 꺾이는 구간을 못 잡음 |
| `min_samples_leaf` | leaf 노드 최소 샘플 수 | 크게 잡으면 과적합 방지(노이즈 많은 그룹3에 특히 유효할 수 있음) |
| `max_features` | 분기마다 고려할 피처 후보 수 | `"sqrt"`가 회귀 기본값보다 분산을 더 줄여줌 |
| `random_state` | 재현성용 시드 | CV 비교할 때 반드시 고정 |

### 이 프로젝트에서 한계

- 트리 개수가 많으면 예측 속도/모델 크기가 커짐.
- 극값(예: 정격출력 근처)을 트리 평균 특성상 살짝 과소예측하는 경향이 있을 수 있음(각 리프의 평균으로 수렴하는 성질).
- 순차적으로 오차를 보정하는 방식이 아니라서, 같은 트리 개수 기준으로는 보통 LightGBM류(gradient boosting)보다 최종 정확도가 낮은 경우가 많음.

## LightGBM (LGBM)

### 동작 원리

RandomForest처럼 트리를 여러 개 쓰지만 **만드는 방식이 다름**:

1. 처음엔 아주 단순한 예측(예: 전체 평균)에서 시작.
2. 그 예측이 **틀린 정도(잔차, gradient)** 를 계산.
3. "그 잔차를 줄이는 방향으로" 다음 트리를 하나 학습시켜서 이전 예측에 **더해줌**.
4. 이 과정을 트리를 하나씩 추가하며 반복(`n_estimators`/`num_boost_round`번) — 트리들이 병렬이 아니라 **순차적으로 서로의 오차를 보정**해나감(gradient boosting).

"Light"인 이유는 두 가지 최적화 때문:
- **Leaf-wise 트리 성장**: 보통 트리는 같은 깊이의 노드를 다 채우고 내려가는데(level-wise), LightGBM은 "지금 가장 손실을 많이 줄일 수 있는 leaf"부터 먼저 쪼갬 — 같은 트리 개수/시간 대비 더 정확한 트리를 만듦(대신 과적합엔 더 취약해서 `max_depth`/`num_leaves` 제어가 중요).
- **히스토그램 기반 분기 탐색**: 연속값을 구간(bin)으로 나눠서 분기 후보를 빠르게 찾음 — 대용량(우리 데이터처럼 26k+ 시간, 수십개 피처)에서도 빠름.

### 왜 이 문제에 적합한가

- **순차 보정(boosting) 구조라 RF보다 보통 더 정확함** — 특히 파워커브의 "꺾이는 지점"이나 적격시간(CF≥10%)만 봤을 때처럼 더 어려운 서브셋에서 잔차를 계속 줄여나가는 게 유리.
- **범주형 피처(그룹 ID 등)를 원-핫 없이 네이티브로 처리** 가능.
- 대용량 grid×시간 데이터에서도 학습이 빠름 — 실험 반복(피처 추가/제거하며 CV 여러 번 돌리기)에 유리.
- **커스텀 loss/objective**를 넣기 쉬움 — 나중에 FICR 구간표가 확정되면, 오차구간(≤6%, ≤8%)에 맞춰 손실함수를 직접 짜서 "정확도 밴드에 들어가게" 유도하는 것도 LightGBM 쪽이 RF보다 자연스러움(PLAN.md §1.3에서 언급한 부분).

### 주요 파라미터

| 파라미터 | 의미 | 실무 감 |
|---|---|---|
| `num_leaves` | 트리 하나의 leaf 개수 (LightGBM 핵심 파라미터) | 클수록 표현력↑ 과적합↑. `2^max_depth`보다 작게 잡는 게 정석 |
| `learning_rate` | 트리 하나가 잔차를 얼마나 세게 보정할지 | 작을수록 안정적이지만 `n_estimators`를 늘려야 함 (보통 0.01~0.1) |
| `n_estimators` | 부스팅 라운드(트리) 수 | learning_rate와 세트로 튜닝, early stopping과 함께 쓰는 게 일반적 |
| `min_child_samples` | leaf 최소 샘플 수 | RF의 `min_samples_leaf`와 같은 역할, 과적합 방지 |
| `feature_fraction` / `bagging_fraction` | 매 트리/라운드마다 피처·행을 일부만 샘플링 | RF의 랜덤성을 boosting에도 섞어서 과적합 억제 |
| `objective` | 손실함수 (`regression`=L2, `regression_l1`=MAE 등) | 나중에 커스텀 loss로 교체 가능 |

### 이 프로젝트에서 한계 / 주의점

- RF보다 **과적합에 민감** — `num_leaves`, `min_child_samples`, `learning_rate`+`n_estimators` 조합을 잘 맞춰야 함. 특히 라벨 이력이 짧은 group_3은 과적합 위험이 더 큼(정규화 더 세게, 또는 조기종료 기준을 더 보수적으로).
- 그리드서치 없이 기본값만 쓰면 RF보다 오히려 못할 수도 있음 — RF보다 "적당히 잘 나오는 기본값"에 덜 관대함, 튜닝이 성능에 더 크게 좌우함.
- 시계열이라 랜덤 K-fold가 아니라 **시간 기준 split**으로 검증해야 함(미래 정보가 과거 학습에 새는 걸 방지) — 이건 RF도 마찬가지지만 boosting은 순차 보정 특성상 validation 방식이 틀리면 과적합을 더 늦게 알아챌 수 있음.

## 둘을 비교하는 이유 (baseline 선정 관점)

| | RandomForest | LightGBM |
|---|---|---|
| 학습 방식 | 병렬(bagging) | 순차(boosting) |
| 튜닝 부담 | 낮음 — 빠르게 baseline | 높음 — 잘 맞추면 더 정확 |
| 대용량/반복실험 속도 | 보통 | 빠름 |
| 커스텀 loss(FICR 대응) | 어려움 | 쉬움 |
| 과적합 성향 | 상대적으로 안전 | 파라미터 잘못 잡으면 위험 |

**결론 감**: RandomForest로 빠르게 뼈대(파이프라인/CV/베이스라인 점수)를 잡고, LightGBM으로 갈아타면서 본격적인 성능 개선 — `windcon/docs/PLAN.md` §1.5 우선순위와도 일치.
