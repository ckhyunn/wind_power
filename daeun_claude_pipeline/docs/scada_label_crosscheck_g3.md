# SCADA-라벨 교차검증 (담당: 윤다은) — g3(unison) denoise 재점검 결과

**대상:** `model_A.py`의 `g3mask()`(group3 라벨 정제, unison SCADA와 1000kWh 초과 어긋난 시간 제외)
**데이터:** `model_A/cleaned/scada_unison_clean.csv`(10분 단위, 5기 합산), `model_A/cleaned/train_labels_clean.csv`, `model_A/output_2024/actual_2024.csv` + `pred_A_blend_2024.csv`(2024 실측 교차검증용)
**주의:** `model_A.py`는 건드리지 않음 — 분석 스크립트만 별도로 작성, 재현 방법은 맨 아래 참고.

---

## 1. denoise 임계값(1000kWh) — 자연스러운 경계가 아님

SCADA-라벨 잔차(둘 다 유효한 17,538시간 기준) 절대값 분위수: 75%=393, 90%=785, **95%=1091**, 99%=1845.
임계값을 300~5000까지 sweep 하면 마스크되는 비율이 31.8% → 19.3% → 9.6% → **6.1%(현재 1000)** → 2.0% → 0.79% …로
**매끈하게 연속 감소**함 — 중간에 뚝 떨어지는 지점(노이즈/정상의 자연스러운 경계)이 없음. 즉 1000kWh는 데이터가
뒷받침하는 임계값이라기보다 임의로 고른 절대값에 가까움.

## 2. 마스크되는 시간대의 성격 — "정지 패턴"이 아니라 "중간~고발전 구간 불일치"

현재 마스크(1073건, 2023+2024)의 특성: 평균 SCADA 10,775kWh / 라벨 11,080kWh(둘 다 cap 21,000의 절반 수준,
0 근처 아님), 평균 풍속 8.9m/s. "SCADA≈0인데 라벨은 큼"(SCADA 정지/통신두절 의심) 케이스는 1건, "라벨≈0인데
SCADA는 큼"(정산 미반영 의심) 케이스도 1건뿐 — 즉 단순 on/off 정지 패턴이 주된 원인이 아니라, **정상 가동
중의 SCADA-정산 수치 불일치**가 대부분임.

## 3. 핵심 발견 — 커튼먼트(출력제한) 패턴은 이 마스크가 원리적으로 못 잡음

"풍속>8m/s인데 발전량<정격10%"(바람은 있는데 출력 없음 = 커튼먼트 의심) 케이스가 전체 89건(2023+2024) 있는데,
그중 현재 denoise 마스크에 걸리는 건 **3건뿐**. 이유: 커튼먼트가 걸리면 SCADA와 라벨이 **함께** 낮아지므로
둘의 잔차 자체가 작아서 이 방식으로는 검출이 안 됨.

**2024년 실측 예측오차율로 직접 검증함** (`output_2024/actual_2024.csv` vs `pred_A_blend_2024.csv`, group3 기준
전체 평균 오차율 12.75%):

| 후보군 | 2024건수 | 평균 오차율 | 전체 대비 |
|---|---:|---:|---:|
| denoise 마스크(SCADA-라벨 잔차>1000) | 557 | 13.40% | 1.05x — 사실상 무관 |
| `kpx_group_3_longzero`=1 | 241 | 19.07% | 1.50x |
| **커튼먼트 후보(풍속>8m/s, 출력<정격10%)** | **51** | **52.45%** | **4.11x** |

지금 쓰는 denoise 마스크는 실제 예측 오차와 거의 상관없고(1.05x), 대신 **커튼먼트 후보 51시간이 평균보다
4배 이상 오차가 큼** — model_A가 가장 못 맞추는 구간이면서 지금 파이프라인엔 이걸 걸러내거나 표시하는 로직이
전혀 없음. g3의 90%+ 발전량 구간 FICR이 0.03 수준으로 심각하게 낮은 것과 연결될 가능성이 높음.

부가 발견: 라벨에 이미 있는 `kpx_group_3_longzero` 플래그(2024년 241시간)가 denoise 마스크와 **전혀 안 겹침**
(0/557) — 이 플래그가 정확히 뭘 의미하는지(정비/장기정지 추정) 확인 후 별도 마스크 후보로 검토 필요.

계절 패턴: 2024년 상위 오차 100시간 중 **1월 48건, 7월 13건**으로 쏠림 — 겨울철 착빙/컷아웃, 여름 태풍철
출력제한 등 계통 지시 이력과 대조해볼 가치 있음.

## 4. 권고 (우선순위)

1. **denoise 임계값 자체 튜닝은 우선순위 낮음** — 실제 오차와 무관함이 확인됨(1.05x)
2. **커튼먼트 검출을 SCADA-라벨 잔차가 아니라 "풍속 대비 출력 부족" 자체로 별도 구현** — (a) 해당 시간 학습
   제외 또는 (b) 캘린더/커튼먼트 플래그 피처로 인코딩. 현재까지 나온 것 중 근거가 가장 확실한 다음 스텝
3. `longzero` 플래그(241건)가 실제 정비/장기정지와 일치하는지 확인, 필요시 별도 마스크
4. 1월/7월 오차 집중 구간을 실제 계통 커튼먼트 지시 이력과 날짜 단위로 대조
