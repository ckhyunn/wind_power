# kma_api

기상청 API Hub 단기예보(격자) 수집 — `fetch_kma_shrt_grd.py`

기상청 API Hub **2.1 단기예보** (`nph-dfs_shrt_grd`)에서 예보 격자를 받아, 원하는 지점 한 곳의
값만 뽑아 DataFrame/CSV로 저장한다. 기본 지점은 **태백**.

### 준비

```bash
cp .env.example .env
# .env 에 KMA_API_KEY 입력 (.env 는 .gitignore 처리되어 있음)

set -a && . ./.env && set +a
```

### 실행

```bash
# 태백, 전체 예보변수 14종
python3 fetch_kma_shrt_grd.py --tmfc 2026081117 --tmef 2026081200

# CSV로 저장
python3 fetch_kma_shrt_grd.py --tmfc 2026081117 --tmef 2026081200 --out taebaek.csv

# 다른 지점 — 위경도로 지정 (격자 좌표는 자동 변환)
python3 fetch_kma_shrt_grd.py --tmfc 2026081117 --tmef 2026081200 --latlon 37.7519 128.8761

# 응답 원문 확인
python3 fetch_kma_shrt_grd.py --tmfc 2026081117 --tmef 2026081200 --raw --vars TMP
```

출력 예 (태백, 2026-08-11 17시 발표 → 2026-08-12 00시):

```
grid cell (nx, ny) = (95, 119)
      tmfc       tmef  nx  ny var  value  valid_cells
2026081117 2026081200  95 119 TMP   16.0         9295
2026081117 2026081200  95 119 WSD    4.3        30364
2026081117 2026081200  95 119 SKY    3.0        30364
2026081117 2026081200  95 119 REH   95.0         9295
2026081117 2026081200  95 119 WAV    NaN        22206
```

`WAV`(파고)는 해상 전용이라 내륙 지점에서는 `NaN`이 정상이다. `valid_cells`가 변수마다 다른 것도
정의역이 달라서다 — 육상 변수 9,295셀, 바람·하늘 30,364셀, 파고 22,206셀.

### 요청 인자

| 인자 | 설명 |
|---|---|
| `tmfc` | 발표시각 `YYYYMMDDHH` (KST). **02·05·08·11·14·17·20·23시만 유효** |
| `tmef` | 발효시각 `YYYYMMDDHH` (KST). 1시간 간격, `tmfc` 이후 |
| `vars` | 예보변수 1종. `TMP TMX TMN UUU VVV VEC WSD SKY PTY POP PCP SNO REH WAV` |
| `authKey` | 발급 인증키 (환경변수 `KMA_API_KEY`로 전달) |

**지역 파라미터는 없다.** 이 API는 한 번 호출에 전국 격자를 통째로 돌려주고, 지점 선택은 응답에서
격자 셀을 골라내는 방식이다. `reg`(예보구역코드)는 별도 API(`fct_afs_dl.php`)용이라 여기서는
동작하지 않는다.

### 응답 형식

헤더도 좌표도 없는 실수 배열이 줄당 20개씩 나열된다. 실제 호출에서 **37,697개 = 149 × 253**
(동네예보 격자)이 확인되었고, 결측은 `-99.00`이다. 행 순서는 **ny 오름차순**이라 인덱스는
`(ny-1) * 149 + (nx-1)`.

ny 방향은 문서가 아니라 조회로 확정했다 — 반대로 읽으면 태백·부산·서귀포가 전부 결측 셀에
떨어지고, 오름차순이면 8월 자정 기준 16.0 / 24.0 / 23.0 ℃가 나온다. 서울은 판별에 못 쓴다
(253−127+1 = 127로 자기 자신에 매핑됨).

### 지점 좌표

`latlon_to_grid()`는 기상청 공개 변환식(`dfs_xy_conv`, Lambert conformal conic)을 그대로 구현한
것이다. 공식 기준점으로 교차검증됨 — 서울시청 (37.5665, 126.9780) → **(60, 127)**.
태백시청 (37.1641, 128.9856) → **(95, 119)**.

### 확인되지 않은 사항

- `tmfc` 대비 `tmef`를 얼마나 미래까지 넣을 수 있는지(예보 가능 범위)
- `vars`에 여러 변수를 한 번에 넣을 수 있는지 — 공식 예시가 단일뿐이라, 이 스크립트는 변수별로
  개별 호출해 합친다. 다중 지정이 가능하든 아니든 결과는 같다.

### 오류 확인 순서

| 증상 | 확인할 것 |
|---|---|
| 전 셀이 결측 | `tmfc`가 발표시각(02·05·…·23)인지. 다른 시각은 에러가 아니라 빈 격자로 응답 |
| 인증 실패 | 키 유효기간·일일 호출한도. 이 API는 키 오류도 HTTP 200 + 본문 텍스트로 응답하므로 상태코드만 봐서는 알 수 없다 |
| 값 개수 불일치 | 응답 레이아웃 변경 가능성. `--raw`로 원문 확인 |
| 해당 지점만 NaN | 그 변수의 정의역 밖일 수 있음 (예: 내륙의 `WAV`) |

### API 키 관리

- 키는 `.env`에만 두고 소스에는 절대 넣지 않는다. `.env`는 `.gitignore` 처리됨
- URL에 `authKey`가 섞여 들어오면 스크립트가 실행을 거부한다 (키가 커밋되는 사고 방지)
- 키가 한 번이라도 소스나 로그에 노출됐다면 재발급이 정답이다
